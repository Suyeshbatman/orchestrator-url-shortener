# API reference

Two HTTP APIs: the **shortener** (`:8085`) and the **orchestrator** (`:8086`). Both serve OpenAPI at
`/v3/api-docs` and Swagger UI at `/swagger-ui.html`. The shortener's document is also checked in at
`shortener-service/src/main/resources/static/openapi.yaml`, regenerated by `LinkApiIT`.

## Conventions (both APIs)
| | |
|---|---|
| Format | JSON (`application/json`); timestamps are ISO-8601 instants in UTC (`2026-11-21T10:15:30Z`) |
| Auth | `X-API-Key: <key>` on every `/api/**` call. Keys are configured as `name:sha256hex(key)` and compared in constant time; the key itself is never stored |
| Errors | RFC 9457 Problem Details (`application/problem+json`): `type` (a stable URI such as `/problems/link-not-found`, part of the contract), `title`, `status`, `detail`, `instance`, and `correlationId` when present |
| Correlation | `X-Correlation-Id`: a safe client value (`[A-Za-z0-9._-]{1,64}`) is kept, otherwise generated. Echoed on the response and present on every log line (shortener) |
| Versioning | The shortener's management API is under `/api/v1`. A breaking change gets a new prefix. Problem `type` URIs never change meaning |

## Shortener (`:8085`)

### `POST /api/v1/links` — create a short link
Auth: any API key; the key's name becomes the link's owner. Rate limit: `create` scope, per API key.

| Header | |
|---|---|
| `Idempotency-Key` | Optional. The same key and body replay the stored response (`Idempotent-Replayed: true`); the same key with a different body is `422`. Kept for `shortener.idempotency.ttl` (24 h), scoped per API key |

Body (`CreateLinkRequest`):
```json
{ "url": "https://example.com/some/long/path", "customAlias": "promo-2026" }
```
| Field | Rules |
|---|---|
| `url` | required, ≤ `shortener.url.max-length` (2048). Scheme in `allowed-schemes` (`http`, `https`). No `user:pass@`. Host present, not this service's own host. With `block-private-networks`: canonical IPv4 only, and the host must resolve to public addresses within `dns-timeout` (fail closed) |
| `customAlias` | optional, 4–32 characters of `[A-Za-z0-9_-]`, not reserved (`api`, `actuator`, `admin`, `health`, `swagger-ui`). Unique case-insensitively among aliases |

`201 Created` with `Location: /api/v1/links/{code}` and `Idempotent-Replayed: true|false`:
```json
{
  "code": "aZ3k9Qb", "shortUrl": "http://localhost:8085/aZ3k9Qb",
  "originalUrl": "https://example.com/some/long/path", "customAlias": false,
  "status": "ACTIVE", "createdAt": "2026-11-21T10:15:30.123456Z", "updatedAt": "2026-11-21T10:15:30.123456Z"
}
```
Errors: `400 validation-failed` (body fields), `400 malformed-request` (not JSON), `400 invalid-url`
(with `reason`: `TOO_LONG`, `MALFORMED`, `SCHEME_NOT_ALLOWED`, `MISSING_HOST`,
`USERINFO_NOT_ALLOWED`, `NON_CANONICAL_IP`, `PRIVATE_ADDRESS`, `UNRESOLVABLE_HOST` or
`SELF_REFERENCE`), `400 invalid-alias`, `400 invalid-idempotency-key`, `401 unauthorized`,
`409 alias-taken`, `422 idempotency-key-reused`, `429 rate-limited`.

### `GET /api/v1/links/{code}` — link metadata
Auth: the owner's key. Another owner's link answers `404`, so its existence isn't revealed. Deleted
links are returned with `status: DELETED`. `200` with the body above, or `404 link-not-found`.

### `DELETE /api/v1/links/{code}` — soft delete
Auth: the owner's key. Idempotent. `204`, or `404 link-not-found`. The row stays; the redirect stops.
On `main` the cache is not evicted (known issue BF-1, `docs/known-issues.md`): a cached link can
keep redirecting until its TTL expires.

### `GET /api/v1/links/{code}/stats?from=YYYY-MM-DD&to=YYYY-MM-DD` — click analytics
Auth: the owner's key. UTC days, both inclusive. The default is the last 30 days and the maximum
`shortener.analytics.max-range-days` (90). Clicks appear about a second after the redirect.
```json
{ "code": "aZ3k9Qb", "from": "2026-11-01", "to": "2026-11-21", "totalClicks": 1284,
  "uniqueVisitors": 911,
  "clicksByDay": [ { "day": "2026-11-01", "clicks": 40 } ],
  "topReferrers": [ { "host": "news.ycombinator.com", "clicks": 300 } ],
  "byUaFamily": { "Chrome": 700, "Safari": 300 } }
```
- **`uniqueVisitors`** is a HyperLogLog estimate (about 0.81 % error), or exact from the database
  when Redis is down. The visitor hash rotates daily, so a visitor seen on two days counts twice.
- **`clicksByDay`** is zero-filled for every day in the range.

Errors: `400 invalid-stats-range`, `404 link-not-found`.

### `GET /{code}` — redirect (public)
`code` matches `[A-Za-z0-9_-]{4,32}`, so it never shadows `/api`, `/actuator` or `/swagger-ui`.
Rate limit: the `redirect` scope, per visitor fingerprint.
- `302 Found` (`shortener.redirect.status`, 301–308) with `Location` and
  `Cache-Control: max-age=0, private`, so every click reaches the service and a delete takes effect
  (ADR-0002).
- `404 link-not-found`: unknown or deleted.
- The click is published asynchronously and is dropped, never waited for, when the queue is full
  (ADR-0004).

### Rate-limit headers
Responses of limited endpoints carry `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`
(seconds, rounded up; IETF draft-ietf-httpapi-ratelimit-headers). A `429 rate-limited` also carries
`Retry-After`.
- **When Redis is unavailable:** creation falls back to a per-instance bucket, and redirects are
  allowed unmetered (fail open).

## Orchestrator (`:8086`)
- **Roles:** `OPERATOR` keys (`orchestrator.operator-keys`) start and steer runs. `APPROVER` keys
  (`orchestrator.approver-keys`) decide approvals. Reads need any valid key. A principal can be in
  both lists.
- **Commands:** they are accepted asynchronously (`202`) and applied by the run's coordinator in
  order. Follow the effect through the events.

### Runs
| Method and path | Role | |
|---|---|---|
| `POST /api/runs` | OPERATOR | Start a run. `201` with a `RunView` |
| `GET /api/runs` | any | All runs (`RunSummary[]`) |
| `GET /api/runs/{id}` | any | `RunView`: the run and its stage graph with statuses, attempts, loops and timings |
| `GET /api/runs/{id}/dag.mmd` | any | The stage graph as Mermaid text, coloured by status |
| `GET /api/runs/{id}/events?afterSeq=N` | any | The event log after `N` (hash-chained `EventView`s) |
| `GET /api/runs/{id}/audit/verify` | any | Recompute the hash chain: `{valid, eventCount, firstBrokenSeq, problem, headHash}` |
| `POST /api/runs/{id}/answers` | OPERATOR | Answer blocking questions; the requirements stage re-runs with them |
| `POST /api/runs/{id}/requirements` | OPERATOR | Amend the requirement. Re-plans: stages that read it are invalidated and their approvals voided |
| `POST /api/runs/{id}/halt` | OPERATOR | Safe stop: nothing new starts; in-flight attempts get `orchestrator.safe-stop-grace`, then `RUN_HALTED` |
| `POST /api/runs/{id}/resume` | OPERATOR | Halted stages become ready again |
| `POST /api/runs/{id}/rollback` | OPERATOR | Restore the workspace to a stage's checkpoint; that stage and everything after it run again |

Start a run (`CreateRunRequest`). Give `scenarioId` (uses `scenarios/<id>/requirement.md` and its
replay fixtures) **or** `requirementText`:
```json
{ "scenarioId": "greenfield-qr-code", "mode": "GREENFIELD", "autonomyLevel": "L1_SUPERVISED" }
{ "requirementText": "Add a QR code endpoint…", "mode": "BROWNFIELD" }
```
- `mode`: `GREENFIELD` | `BROWNFIELD`.
- `workflow` (optional): a file in `config/workflows` without `.yml`. The default is
  `sdlc-standard`; `sdlc-fanout` runs implementation as one sub-stage per code task
  (`implementation.T1`, …). An unknown workflow is a 400.
- `autonomyLevel`: `L0_SUGGEST` | `L1_SUPERVISED` (default) | `L2_TRUSTED` (see
  `workflows-and-policies.md`).

Other bodies:
```json
POST /answers       { "answers": [ { "ambiguityId": "AMB-1", "answer": "…" } ] }
POST /requirements  { "text": "the whole amended requirement" }
POST /halt          { "reason": "optional" }
POST /rollback      { "toStage": "implementation", "reason": "optional" }
```
Responses of commands: `202 {"runId": "run-…", "command": "answers"}`.

### Approvals
| Method and path | Role | |
|---|---|---|
| `GET /api/approvals?status=PENDING&runId=…` | any | Approvals, newest first. `status`: `PENDING`, `GRANTED`, `REJECTED` |
| `POST /api/approvals/{id}` | APPROVER | Decide: `{"decision": "APPROVE" | "REJECT", "comment": "…"}`. `202` |

An approval (`ApprovalView`) has:
- `id` (`<runId>:<seq of APPROVAL_REQUESTED>`), `runId`, `stageId`, `status`;
- `reason`: why it waits, e.g. `Scope sign-off`, a policy match such as
  `policy: file_write …/V3__link_expiry.sql needs approval (CHG-001-schema-migration)`, or
  `human input needed: …` for blocking questions;
- `summary`: the stage's summary, `riskScore`, `diffStats`, `matchedPolicies` and the artifacts to
  review;
- `requestedAt`, `decidedAt`, `decidedBy`, `comment`.

Decision rules:
- **Only a human approver counts.** A principal with the `APPROVER` role, never an agent or the
  system.
- **A rejection re-runs the stage** with the comment as feedback. Rejecting an approval that is due
  *before* a stage runs (publish) fails that stage, so the action never runs.

### Artifacts
| Method and path | | |
|---|---|---|
| `GET /api/runs/{id}/artifacts` | any | `ArtifactSummary[]`: id `run:stage:type:vN`, version, content hash, producer, model, prompt hash, inputs |

### Metrics
`GET /api/metrics/summary` (any key): the reliability summary computed from all event logs.

| Field | Meaning |
|---|---|
| `runs` | total, completed, failed, halted, in progress |
| `runSuccessRate` | completed / (completed + failed) |
| `stages`, `stageSuccessRate` | successes (`STAGE_SUCCEEDED`, or approval of a stage that ran) / (successes + failures); attempts, retries, fallbacks |
| `retryRate`, `rollbacks`, `rollbacksPerRun` | |
| `mttr` | mean time from a stage's first failure signal (retry, fallback, failure, validation loop-back) to its next success |
| `endToEnd`, `endToEndExcludingApprovalWait` | p50 / p95 of completed runs, with and without the time spent waiting for humans |
| `approvalWait` | mean, max, number decided |

Also `/actuator/health` and `/actuator/prometheus`. The dashboard is served at `/`.
